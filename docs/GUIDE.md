## 0. 快速开始

**登录**：浏览器打开工作台地址 → 输入用户名 / 密码 → 进入自己的工作区（dsh 会话界面）。

**界面导航**：
- 左侧栏上方：`+ 新会话`、工作区与会话列表；
- 左侧栏左下角：**助理** / **技能·连接器** / **自动化** / **公告** / **团队资料** / **用量**（以上六个点开 = 整页界面）/ **设置**（6 个设置页）。

**桌面端（可选）**：
1. 本机桌面「**DSH 团队工作台（应用）**」快捷方式 —— 独立窗口，双击即用；
2. 浏览器地址栏「**安装应用**」（PWA，适合 https/localhost；局域网 http 环境用第 1 种）；
3. 转发给成员：`%LOCALAPPDATA%\desk-anywork\desk-app\DSH工作台-应用模式（成员可转发）.bat`。

> 桌面端只是给同一网页套壳 —— **网页端更新，桌面端自动是最新的**。

**手机**：同一 Wi-Fi 下浏览器直接打开工作台地址即可。手机端为移动优化布局：左侧栏展开是**覆盖式抽屉**（约占 2/3 宽、不压暗、不再压内容），**不压暗、点右侧不会自动收起**（右侧对话/运行输出照常可见可操作；关闭用右上角「收起侧边栏」）。**顶边把手往下拖，侧边栏可以在原位「从上往下缩」**（底边固定、最扁只留最底一行如「设置」；点一下把手=全高/一行快切；缩得很小时点输入框会自动让位、不挡键盘）；设置页与六个侧栏入口均为**全屏整页**（关闭：右上角「← 返回对话」/ 点界面外任意处）。

## 1. 工作台基本操作

| 操作 | 怎么做 |
|---|---|
| 开新会话 | 侧栏 `+ 新会话`（可选「Agent 预设」角色，默认 `team-assistant`） |
| 后台任务 / 子代理 | 直接对 agent 说，例如「后台跑 xxx」「派个子代理做 yyy」；会话头部有任务条，点开看输出 |
| 会话导出（存档） | 会话头「Session log / 导出」→ 下载 ZIP（含全部消息）；**重要会话删除前先导出** |
| 跨会话检索 | 对 agent 说「搜一下我们之前关于 xxx 的讨论」——agent 会用 `session_search` 在你有权限的会话里搜 |
| 会话删除 | 见 [§2.3 会话管理](#23-会话管理删除管理员批准制) |

## 2. 设置页（6 个）

### 2.1 工作台用量

- **入口**：侧栏「**用量**」（整页）——本月费用大数字、请求次数、预算进度条、最近请求明细；**管理员**还能看到「近 7 天团队用量」。设置 → 工作台用量 里也有一份（同一数据）。
- **随手看**：会话顶栏右侧一行小字「本月 ¥…」（**手机端不显示**）——点开出小气泡（今日 / 本月 / 预算占比），点「查看详情」打开用量整页；预算用到 **80% 变黄、100% 变红**。
- **看什么**：本月 token 用量、费用、按天趋势。
- **口径**：按 DeepSeek 官方**峰谷价**计价 —— 高峰 = 北京时间周一~五 9:00–12:00 / 14:00–18:00，其余时段（含整个周末）半价；走外部通道的调用按该通道的价目表计费。
- **预算**：每月用量到预算 **80% / 100%** 时自动推管理员一条告警（每档每月一次）。

### 2.2 任务板（含提交·验收）

- **入口**：设置 → 任务板（全员可见）；「待验收 N」筛选直看待评审的提交。
- **怎么用**：
  1. 「新建任务」：标题 + 备注 + 可指派成员；无主任务**任何成员可「接领」**；
  2. 干活的人完成后点「**提交验收**」：可附**提交内容**（每行一条：commit 链接 / sha + 说明）、**提交说明**，并**可关联一条 DSH 会话**——用 AI 干的活就选干这条活的那次会话（评审人可顺着它回看全过程）；
  3. 创建者 / 管理员在卡片上「**通过**」（任务转已完成）或「**打回**」（退回进行中，必填理由；提交人改完可再交）；提交人在待验收期间可「**撤回**」重交；
  4. 提交通知创建者与管理员，通过 / 打回通知提交人（走「通知」页配的通道）。
- **权限**：指派/创建人可提交；管理员、发起人可通过/打回；接领是例外（人人可接无主任务）。
- **人机可分辨**：约定 AI 代写的 git 提交带 `Generated-by: dsh-anywork-agent` 尾注（见工作区 README），配合卡片的「关联会话」，评审重点与事后审计都能落地。

### 2.3 会话管理（删除·管理员批准制）

- **入口**：设置 → 会话管理（全员可见）。
- **成员怎么删会话**：在「我的会话」里找到目标 → **申请删除** → 变成 ⏳ 待管理员确认（可「撤销」）；管理员会收到一条通知，批准后生效。下方「我的申请」随时看审批状态。
- **管理员怎么删**：
  - 「待审批」里 **批准删除 / 驳回**（批准=立即执行）；
  - 「成员会话」：下拉选成员 → 加载会话 → 对任意一条**直接删除**；
  - 自己的会话在「我的会话」行上直接有「删除」。
- **注意**：
  - **删除不可恢复**（比"归档"彻底）——重要会话先按 [§1](#1-工作台基本操作) 导出 ZIP 存档；
  - 执行删除时，对应实例会**自动重启约 10~30 秒**（引擎升级后启动稍慢，属正常；页面会自动恢复）；
  - 已归档的会话也会一并被清除。

### 2.4 团队资料（已移至侧栏）

> 原「知识库」「公司盘」两个设置页已合并为**侧栏「团队资料」**入口（点开 = 整页）——文件与笔记一个门进去，详见 [§3.5](#35-团队资料)。


### 2.6 成员管理（管理员）

- **入口**：设置 → 成员管理（仅管理员；成员打开会看到权限提示）。
- **新增成员自动配置**：提交后系统自动配好其工作台（钥匙 → 端口 → 插件 → 实例拉起），约 1 分钟内可登录使用，无需任何手工步骤。
- **删除成员自动回收**：删除后实例立即停止，约 15 秒内自动清理其工作台与数据（**不可恢复**，重要数据请先备份）。
- **团队模型配置（管理员）**：「设置 → 模型」页底部有「团队共用模型 Key」和「模型通道」两个模块——换 Key 约 5~10 秒全队生效；通道按模型名分流到其它上游（加入通道支持**服务商预置**：选商 → 贴 key → 勾模型，无需查文档）。成员在模型页只看到**只读**的团队配置（不能改，可直接用模型）。
- **内容**：成员列表（在线状态、最后登录、近 7 日用量趋势、月预算）；「新建成员」返回虚拟钥匙——**系统已自动写入其工作台，无需转交**（仅存档需要时复制）；「删除成员」数据留档。
- **注意**：若服务器以环境变量提供真 key（DESK_REAL_KEY），模型页模块里为只读（以实际显示为准）。

### 2.7 通知

- **入口**：设置 → 通知（全员可看记录；通道管理仅管理员）。
- **通道（12 种）**：webhook / 微信 / Telegram / WhatsApp / 飞书 / 钉钉 / 企业微信 / Discord / Slack / Microsoft Teams / ntfy 手机推送 / Zoom —— 添加时选类型、按「目标格式」填写、可随时启用/停用、删除、「发送测试」验证。开通步骤见 [§5.1](#51-通知通道开通指南)。也可直接在 **侧栏 →「技能·连接器」** 的平台卡片上「连接」（管理员）。
- **提醒列表**：当前所有定时提醒（新增方式见 [§5.2](#52-定时提醒3-种姿势)；删除在此页或让管理员处理）。
- **通知记录**：最近发送结果（成功/失败原因），排障先看这里。

### 2.8 运维（管理员）

- **入口**：设置 → 运维（仅管理员）。
- **看什么**：各服务（systemd 单元）运行状态、门户/网关/各实例端口探活、备份目录与最近备份时间、磁盘占用。
- **用途**：排障第一屏 ——「哪里不对劲」先看这里。

## 3. 侧栏模块（6 个）

> **打开方式（电脑与手机一致）**：点侧栏六个入口 = 整个工作区切换成该功能的**整页界面**（左侧栏保留在最左侧，随时换页；同一时间只开一个——直接点另一个入口即可切换）。**关闭**：右上角「← 返回对话」/ 按 `Esc` / **点界面外任意处**。

### 3.1 助理

- **看什么**：**团队角色** —— 团队助理（默认）/ 研究助理 / 文档写手 / 数据整理 / 开发搭档 / 会议秘书；下方还有**引擎自带模式**（标准 / 极简 / PTC / 创造，技术向，随引擎升级更新）。
- **怎么用**：开「新会话」时点输入框上方的角色胶囊选一个即可；**不选 = 默认「团队助理」**。
- **维护**（管理员/自用）：见 [§4.2](#42-agent-预设角色)。

### 3.2 技能·连接器

- **技能**：列出共享技能库全部技能（名称 + 描述），点开可看全文。
- **连接器**（共 **15 张卡**）：**消息平台**（**我的微信**（成员自助扫码，见 [§5.5](#55-我的微信收通知--与助理对话成员自助)）/ Telegram / 飞书 / 钉钉 / 企业微信 / Discord / Slack / Microsoft Teams / WhatsApp / ntfy / 自定义 Webhook）——**管理员**可在卡片上「连接」（填名称 + 目标，即刻生效）和「测试」（真发一条验证）；**会议**（腾讯会议＝存会议链接/会议号、可「打开」；Zoom 同消息通道）；**工作平台**（GitHub / Notion ＝ 贴令牌、在线验证）；**开发工具**（模型网关、Codex、GitHub CLI、知识库/公司盘、技能与预设的状态）。详见 [§5.4](#54-会议与工作平台连接技能连接器)。
- **怎么用**：对 agent 直接说「用 `xxx` 技能做 …」即可；agent 也会按技能描述自动匹配。

### 3.3 自动化

- **看什么**：顶部统计与筛选；中间是**自动化任务卡片**（每张可 **开 / 关 · 立即运行 · 删除**）；底部**执行记录**（最近跑过什么、成败）。
- **快捷动作**：**今日简报**（助理汇总今天的事）/ **任务进度**（任务板速览）/ **全员提醒**（管理员）。
- **新建**：点「＋ 新建」→ 填「做什么」+「什么时候」——支持「每天 9:00」「明天 10 点」「每周一 8:30」这类中文写法；到点助理自动执行、结果推通知。
- **团队规则卡**（管理员可开关）：任务验收提醒 / 预算 80% 告警 / 删会话提醒 / 反馈提醒。
- 老的「定时提醒」（见 [§5.2](#52-定时提醒3-种姿势)）依然可用，两者并存。

### 3.4 公告板

- **看什么**：团队公告（有新公告时按钮带红点，打开即清零）。
- **成员**：页内可提交「意见反馈」。
- **管理员**：在页内发布 / 删除公告，并查看全部反馈。

### 3.5 团队资料

- **看什么**：一整页两层——**📁 文件**（原公司盘）+ **📝 笔记**（原知识库）。
- **用法就一句话**：原件放「文件」，结论记「笔记」。
- **文件**：按项目 / 客户**新建文件夹**分类；拖拽或点「⬆ 上传」进当前文件夹；每个条目右侧 **⋯** 里可 **移动 / 删除**；点文件夹进入、面包屑返回；单文件 ≤ 50MB；放进来 = 全员可见。
- **笔记**：顶部搜索框全文检索；「＋ 记一条」写一句也算（第一行自动当标题）；点「查看」读全文；删除笔记仅管理员。
- **也可让 agent 代操作**：对 agent 说「把这份文件存到『客户A』文件夹」「把这段结论记到知识库」。

## 4. 团队能力（agent 侧）

### 4.1 团队技能库

- **位置**：服务器共享区 `~/desk-data/skills/`。
- **新增一个技能**：建目录 `<kebab-name>/SKILL.md`，frontmatter 填 `name` + `description` → **保存即被发现**（无需重启，三个实例同时可用）。
- **工作区私有技能**：放自己工作区的 `.dsh/skills/`（只对自己生效，优先级更高）。
- **模板**：仓库 [`skills-template/`](../skills-template/)。

### 4.2 Agent 预设（角色）

- **位置**：`~/desk-data/presets/<id>/`（`preset.yml` + `agent.cordis.yml`）；默认 `team-assistant`。
- **现有团队角色**：团队助理（默认）/ 研究助理 / 文档写手 / 数据整理 / 开发搭档 / 会议秘书。徽标（默认 / Codex 并行）由 `preset.yml` 的 `defaultHint` / `codex` 字段声明。
- **新增角色**：拷贝官方 `standard` 模板改 `preset.yml` → 用 `scripts/apply-team-persona.mjs` 应用人格 → 新会话即可选。
- **模板**：仓库 [`presets-template/`](../presets-template/)。

### 4.3 Codex 子代理与并行工作流

- **单发**：对 agent 说「用 `subagent_codex` 派给 Codex：<任务>」；
- **并行**：说「用 workflow 并行跑这两路：<A>、<B>」；
- **worktree 并行**：装了 `codex-parallel-worktrees` 技能，对 agent 说「按这个技能开两个 worktree 并行做」即可。
- **注意**：Codex 的额度走它自己的账号，**不进入团队用量账单**。

### 4.4 团队 Soul / 工作区规范

- **行为准则**：`~/desk-data/soul/SOUL.md`（软链到各实例）—— 改一处，全员**新会话**生效（运行中的会话会在下一条消息折入）。
- **工作区规范**：你工作区根的 `AGENTS.md`（团队通用规范 + 可加自己的）。
- **模板**：仓库 [`soul-template/`](../soul-template/)。

### 4.5 安全闸门

- **是什么**：20 条危险命令策略挂在所有会话上 —— `deny`（直接拦截，并推一条通知给管理员）/ `ask`（会话里弹审批）/ 放行。
- **规则**：`~/desk-data/hooks/rules.json`（改完下一次工具调用即生效）。
- **实测**：`rm -rf` 等危险命令会被拦截并给出「团队安全闸门拦截…」提示。

## 5. 通知与提醒

### 5.1 通知通道开通指南

在 **设置 → 通知 → 添加通道**（或直接在 **侧栏 → 技能·连接器 → 平台卡片「连接」**，管理员）里选类型，按下面格式填「目标」：

| 通道 | 目标格式 | 开通步骤 |
|---|---|---|
| webhook | `https://你的服务/receive` | 你的接收端会收到 `POST {title, text, source, at}` JSON |
| 微信 | 见 [§5.5](#55-我的微信收通知--与助理对话成员自助) | **成员自助**：技能·连接器 →「我的微信」扫码，通知 + 对话一体（服务器直发，不依赖外部）；管理员也可配置 `weixin` 通道 |
| Telegram | `bot_token\|chat_id` | ① Telegram 找 **@BotFather** → `/newbot` 拿 **bot_token**；② 给你的新 bot 发任意一条消息；③ 浏览器开 `https://api.telegram.org/bot<token>/getUpdates` 找到 `chat.id`；④ 填入 `token\|chat_id` |
| WhatsApp | 三选一（见下） | CallMeBot / green-api / UltraMsg |
| 飞书 | `https://open.feishu.cn/open-apis/bot/v2/hook/…` | 飞书群 → 设置 → 群机器人 → **添加机器人 → 自定义机器人** → 复制 Webhook 地址 |
| 钉钉 | `webhook地址[\|加签Secret]` | 钉钉群 → 群设置 → 智能群助手 → 添加机器人 → **自定义**；安全设置若选「加签」，把 `SEC…` 用 `\|` 接在地址后面 |
| 企业微信 | `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=…` | 企微群 → 右上角「…」→ 群机器人 → 添加 → 复制 Webhook 地址 |
| Discord | `https://discord.com/api/webhooks/…` | 频道设置 → 整合 Integrations → Webhooks → 新建 → 复制 URL |
| Slack | `https://hooks.slack.com/services/…` | api.slack.com/apps 建 app → Incoming Webhooks → 打开开关 → Add to a channel |
| Microsoft Teams | `https://….webhook.office.com/webhookb2/…` | 频道 → 连接器 Connectors → Incoming Webhook → 新建并复制 URL |

**WhatsApp 三种接法**：
- **CallMeBot（个人免费、最简单）**：用要收消息的手机 WhatsApp 给 `+34 644 51 95 23` 发 `I allow callmebot to send me messages` → 收到 **apikey** → 目标填 `callmebot|<apikey>|+86你的手机号`；
- **green-api**：在 console.green-api.com 注册 → 建实例并扫码 → 目标填 `greenapi|<idInstance>|<apiTokenInstance>|<接收号码>`；
- **UltraMsg**：在 ultramsg.com 注册并建实例 → 目标填 `ultramsg|<instanceId>|<token>|<接收号码>`。

> 配好后点「**发送测试**」验证（技能·连接器 页的「测试」按钮效果相同）；多个通道会**同时收到**同一条通知（按启用状态）。

### 5.2 定时提醒（3 种姿势）

1. **对 agent 说**：「30 分钟后提醒我 …」「明天 9 点提醒我带材料」→ agent 用 `desk-remind` 落提醒；
2. **入口/设置**：自动化入口或 设置 → 通知 里查看与删除（新增走第 1 种或让 agent 加）；
3. **命令行（agent 侧）**：`desk-remind "10:00" "开晨会"`。

**时间格式**：`10:00`（已过则顺延到明天）· `明天 09:00` · `09-22 10:00` · `+30m` · `+2h`。
**到点**：自动走**所有已启用通知通道**推送；`desk-remind list` / `desk-remind rm <id>` 管理。

### 5.3 agent 侧命令速查（共享区 `~/desk-data/bin/`，所有实例可用）

| 命令 | 用途 |
|---|---|
| `desk-notify "标题" "正文"` | 主动推一条通知（走所有启用通道） |
| `desk-remind …` | 定时提醒（见上） |
| `desk-kb "标题" "正文"` / `desk-kb list` / `desk-kb search 词` | 知识库沉淀 / 列表 / 搜索 |

### 5.4 会议与工作平台连接（技能·连接器）

「技能·连接器」页除消息平台外还有两组平台卡（**管理员**可连接、成员看状态）：

| 平台 | 怎么连 | 连上做什么 |
|---|---|---|
| 腾讯会议 | 贴常用**会议链接**（https://meeting.tencent.com/dm/…）或 **9~11 位会议号** | 卡片上直接「打开」入会；提醒/公告带会议链接为后续计划 |
| Zoom | 同消息通道（见 [§5.1](#51-通知通道开通指南)），列在会议组方便找 | 推提醒到 Zoom 聊天 |
| GitHub | 贴 **Personal Access Token**（github.com → Settings → Developer settings → Tokens） | 「测试」实时验证并显示账号名；为「AI 代提 issue / 看仓库」打底 |
| Notion | 贴**集成 Token**（notion.so/my-integrations 新建集成后复制） | 「测试」验证集成身份；后续可把笔记/通知写进 Notion 页面 |

- 保存的令牌只有**管理员**能改、能删；成员只看到「已连接 / 未连接」。
- 「测试」失败会给**人话报错**（如 `Token 无效或已过期（HTTP 401）`）——先照着改再测。

### 5.5 「我的微信」——收通知 + 与助理对话（成员自助）

- **入口**：侧栏 技能·连接器 → 连接器 → 第一张卡「**我的微信**」→「连接微信」。
- **怎么接**：弹出的二维码用微信扫一扫（在手机上操作：保存图片 → 微信 扫一扫 → 相册识别）→ 微信里点「确认」→ 完成。**每人扫一次、各接各的机器人**，无需管理员。
- **接完能干嘛**：
  1. **收通知**——团队通知（任务、公告、提醒等）直接进你的微信；
  2. **对话**——直接给这个机器人发消息 = 和**工作台助理**对话，回答发回微信（同一会话在工作台网页里也能接着聊）。
- **第一次收不到消息**：先给机器人随便发一句话激活会话即可（平台机制，一次就行）。
- **换绑 / 重连**：重新扫码即可（卡片上能看到当前连接状态）。

### 6.1 玻璃主题（Aqua，可选）

### 6.2 桌面端

见 [§0 快速开始](#0-快速开始) 的三种用法。要点：桌面端=同一网页的壳，**网页更新即桌面最新**。

### 6.3 工作台增强（新增）

### 6.4 界面语言（中文 / English）

## 7. 模型钥匙与费用

### 7.1 三把钥匙，各管各的

| 钥匙 | 在哪管 | 谁能改 |
|---|---|---|
| **团队共用真 key**（默认上游） | 设置 → 模型 →「团队共用模型 Key」（页底） | 管理员（成员只读） |
| **外部通道 key**（按模型分流） | 设置 → 模型 →「模型通道」（页底） | 管理员 |
| **成员自己的钥匙** | 设置 → 模型（个人 API 卡片，可编辑/替换） | 成员本人 |

- 成员默认使用团队**虚拟钥匙**（`sk-desk-…`，自动播种，无需关心）；
- 管理员加外部通道（如千问）：设置 → 模型 →「模型通道」→「加入通道」——**选服务商 → 贴 API Key → 勾选模型 →「保存并测试连通」**（预置：阿里云百炼/Kimi/智谱 GLM/硅基流动/OpenRouter；选「自定义」可手填任意 OpenAI 兼容地址）。保存后自动做连通测试，失败会给「人话」原因（key 无效/未开通/网络等）。通道会**自动带上该服务商的「单次输出上限」**（预置默认 32768 tokens，防止上游因 `max_tokens` 超限直接拒绝；可在「高级设置」里调整或留空）。
- **通道变更自动同步**：加/停/删通道后，系统会把模型清单自动同步进每位成员的「模型选择器」（各工作台自动重启约 10~20 秒刷新，属正常）。停用/删除的通道，其模型会从选择器中自动撤下。同步时会把通道的**输出上限**一并写入各模型配置（`maxTokens`）——外部供应商对单次输出常有上限（如百炼 32768），超限会直接报 400，这一项保证默认可用。
- 成员想换成**自己的真 key**：在 设置 → 模型 里替换，并**同时把 Base URL 改为 `https://api.deepseek.com`**（否则请求仍打到团队网关会被拒）。
- **防呆守护**：如果有人只把真 key 填进个人卡片、却忘了改 Base URL（这种组合必然无效），系统会在约 15 秒内**自动还原为虚拟钥匙**并记日志（`~/.desk/run/creds-guard.log`），工作台不会因此卡死。

### 7.2 费用口径

- 峰谷价（高峰 = 周一~五 9:00–12:00 / 14:00–18:00 北京时间，其余半价）；
- 外部通道按通道价目表计；
- 预算告警：80% / 100% 每档每月各推一次给管理员。
