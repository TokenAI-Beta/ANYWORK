## Bots（P2 常驻 Bot 会话）

### 发现

dsh 实例提供 `POST /api/<method>`（`{type:'client-request', rpcId, method, payload}`），命名参数走 `payload.args.request`；`session/create`、`session/prompt`、`session/rename`、`session/cancel`、`session/list` 全部可用；实例需要 `instanceAuthCookie(home, origin)` 铸造的 cookie。实验：后台建会话 → 发「只回复 P2OK」→ 文件里读出 `P2OK`，`PROBE-PASS`。

### 实现

- `src/bot-chat.ts`
  - 每成员一份注册表 `/data/desk-data/bot-chats/<username>.json`：`{ bots: { <bot>: { sessionId, createdAt, updatedAt } } }`
  - `ensureBotChat`：无会话才建（cwd = 成员实例家目录），标题 `Bot Chat · <头衔/名字>`；按 Bot 的 model 走 `session/modelCatalog` + `session/selectModel`（best-effort）；首轮注入一次人设（`[设定] …`，读取时隐藏）
  - `sendBotMessage`：`session/prompt`（queue 模式）；会话被外部删时（`session/not-found`）自动清注册表并重建一次
  - `readBotChat`：解码 `session*.jsonl.zstd`，回 user/assistant 文本
  - `cancelBotChat`：`session/cancel`
- `src/portal.ts`（成员级，无需 admin）
  - `GET /portal/api/panel/bot-chat?name=` → `{ sessionId, messages[] }`
  - `POST /portal/api/panel/bot-chat-open | bot-chat-send | bot-chat-cancel`
- `src/panel.ts`：导出 `decodeSessionEventsFile` / `findSessionFileUnder` 供复用

### 修复

「刚建完立刻再次打开会重复建会话」——原实现用会话文件存在性校验，文件尚未落盘导致误判。改为信任注册表，`not-found` 时再重建（实测 open×2 返回同一 sessionId）。
